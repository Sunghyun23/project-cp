# SC-CHARACTER-SELECT — 첫 캐릭터 선택

- 상태: 로컬 프로토타입 구현·렌더링/저장 검증, 실기기 검증 대기
- 담당: AI 작성, 사용자 검토
- 변경일: 2026-11-27
- 근거: D123, [화면 흐름](../screen-flow.md#첫-캐릭터-선택--d123), [시스템](../../03-systems/README.md#첫-시작-캐릭터-선택)

## 확정 사항

신규 플레이어가 자신이 사용할 캐릭터를 선택한다. 인증·진행 조회 후 신규 진행이면 이 화면을 거쳐 SC-FIRST-WEEK로 연결한다. 기존 진행은 저장된 캐릭터·단계로 복귀한다. 기본 캐릭터 선택은 의상 교체와 구분한다.

## AI의 UX 초안

MVP 후보는 남성·여성 각 1명이다(D128). 선택 후보와 선택한 캐릭터의 큰 미리보기, 선택 표시, 확정 행동을 제공한다. 선택 전에는 확정할 수 없음을 설명하고 선택 후 확정 가능하게 한다. 저장 처리 중 중복 확정을 막고 실패하면 선택 내용을 유지해 재시도할 수 있게 하는 방향이다. 응답이 불명확하면 진행을 조회한 뒤 복구하는 안이며 실제 저장 API·중단 정책은 구현 전 정의한다.

사용자 피드백(D129~D130)에 따라 캠핑장을 화면 가득 보여주고, 캐릭터를 잔디 위에 배치하며 하단 나무·천 안내판에서 선택·확정한다. 폰은 제목을 두 줄로 표시하고 넓은 화면은 한 줄로 표시한다. 큰 두 패널 비교 방식은 대체했다. 캐릭터 대기·눈 깜빡임과 기존 호수·잔디 셰이더를 사용한다.

터치·클릭·키보드·패드의 공통 선택/확정을 제공하는 구현이다. Enter/Space는 Godot 기본 UI 확인, 패드 A와 십자키는 UI 액션에 명시적으로 매핑했다. 기기별 물리 입력·접기/펼치기는 추가 검증한다.

확정하면 `select_character` 행동의 `choice`를 `male` 또는 `female`로 보내며 서버가 캐릭터 ID와 `work` 단계·월요일 진입을 한 번에 저장한다. 중복 확정은 버전 검사와 단계 검사로 거부한다. 네트워크 오류·충돌/오류 응답은 선택을 보존하고 재확정 전 저장 조회를 요구한다. 재조회에서 저장이 확인되면 첫 주로, 미저장이면 선택 상태로 복귀한다. 기존 진행은 다시 고르지 않는다. 필드 없는 이전 데이터는 기본 여성 어셋을 표시하고 기존 단계를 유지한다. 이 호환 처리는 플레이어의 성별 정보 추정이 아니다.

## 미정

최종 외형·성능 차이·추후 변경·상세 커스터마이징, 선택 화면에서 계정 변경/뒤로 가기 정책·최종 중단 정책. Figma의 임시 인물 기호를 실제 캐릭터로 확정하지 않는다.

## 완료 기준 초안과 연결

- 신규 진행에서 선택 화면을 거쳐 첫 주로 진입하고 기존 진행은 선택을 반복하지 않는다.
- 선택·확정·처리 중·실패 상태를 구분하고 저장 결과와 실제 사용 캐릭터가 일치한다.
- 폰·PC·펼친 폴드 크기에서 후보·미리보기·확정 행동을 사용할 수 있다.
- 터치·클릭·키보드·패드 각각으로 선택·확정을 수행할 수 있다.
