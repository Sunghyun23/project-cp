# 픽셀 캠핑장 프로토타입

- 상태: 사용자 요청에 따른 프로토타입 구현, 최종 아트 방향과 구분
- 담당: AI
- 변경일: 2026-11-27
- 관련: [세션 흐름](../02-gameplay/session-flow.md), [구현 범위](../07-technical/prototype.md)

## 콘셉트와 어셋

바쁜 평일 뒤 1박 2일 캠핑을 떠나 요리·불멍·커피·토스트로 쉬는 기존 기획을 표현한다. 호수·산·숲은 분위기를 보여주기 위한 AI의 임시 장소 제안이며 신규 지역 시스템을 확정하지 않는다.
사용자가 예쁜 2D 도트 픽셀 배경, 주·야, 귀여운 캐릭터와 움직임을 요청했다. 최종 2D/3D·시점·화면 방향 결정과는 구분한다.

| 파일 | 크기·형식 | 용도 |
|---|---|---|
| `game/assets/pixel/campsite-day.png` | 1672×941 RGB PNG | 호숫가 텐트·의자·테이블·커피·토스트·불 피우기 전 화로 |
| `game/assets/pixel/campsite-night.png` | 1672×941 RGB PNG | 같은 배치의 달·별·랜턴·모닥불 야간 배경 |
| `game/assets/pixel/camper.png` | 1086×1448 RGBA PNG, 투명 | 캐릭터 원본·스타일 참조 |
| `game/assets/pixel/camper-animations.png` | 1536×1024 RGBA PNG, 투명 | 4열×2행, 셀 384×512, 대기 4프레임·걷기 4프레임 |

내장 imagegen으로 직접 생성한 프로토타입 어셋이다. 게임이 참조하는 원본은 저장소의 위 경로에 보관한다. 생성 프롬프트 전문은 [generation-prompts.json](../../game/assets/pixel/generation-prompts.json)과 [animation-prompt.txt](../../game/assets/pixel/animation-prompt.txt)에 기록한다. 낮 이미지를 참조해 구도를 유지한 밤 이미지를 생성했고, 캐릭터는 별도로 생성했다. 생성 도트 스타일 이미지이며 수작업 저해상도 타일셋은 아니다. 캐릭터는 실제 프레임별 스프라이트 시트와 Godot `AnimatedSprite2D`를 사용한다. Godot에서 최근접 필터로 표시한다.

## 움직임과 조작

- 기존 `night` 진행 단계에서는 밤, 나머지는 낮으로 표시한다. 보기 메뉴의 `낮 풍경 / 밤 풍경 / 진행에 맞춰 낮·밤`은 서버 진행을 바꾸지 않는 아트 확인 버튼이다.
- 캐릭터는 대기 4프레임으로 호흡·눈 깜빡임을 표현한다. 바닥을 클릭·터치하면 캠프의 작은 범위에서 이동하며 걷기 4프레임을 초당 7프레임으로 재생한다. 발목을 잘라 변형하는 방식은 제거했다. 위치는 시각 확인용이며 저장·게임 규칙에 영향을 주지 않는다.
- 전용 셰이더로 호수 잔물결·반짝임, 노출된 풀밭의 바람 움직임, 밤 불꽃 흔들림을 표현한다. 불티가 위로 올라간다.
- 야간 조명은 생성 이미지의 빛 표현과 셰이더 명암 변화다. 실제 광원 가림·연료 소모·풀 물리·호수 물리·모닥불 소리는 아직 구현하지 않았다.
- 사이드바는 제거했다. 주차·스탯·계정·갱신·보기는 상단 HUD, 현재 단계와 행동은 하단 카드에 분리한다. 폰은 하단 중앙, 넓은 웹은 왼쪽 아래, 펼친 폴드는 오른쪽 아래에 배치하며 행동은 2열·필요 시 스크롤한다.

## 검증

Godot Web 빌드와 브라우저에서 낮·밤 전환, 실제 대기·걷기 프레임, 배경 셰이더·불티·3D 메시 조명과 그림자 표시를 확인했다. 웹 1280×720·일반 폰 390×844·펼친 폴드 820×920 크기의 브라우저 화면으로 HUD 배치를 확인했다. Android 앱 빌드·실기기·폴더블 접기/펼치기 검증과 장시간 성능 측정은 별도다.

## 로딩 화면

Godot 기본 부트 로고를 끄고 밤 캠핑장·게임 제목·준비 문구·실제 다운로드 진행률을 표시하는 전용 Web 로딩 화면을 적용했다. 진행률은 파일 수신량이며 수신 완료 후 엔진 초기화 중에는 마지막 준비 안내를 표시한다. 인위적인 대기 시간은 추가하지 않는다. 정적 파일은 `no-cache`로 변경해 재방문 시 변경 여부를 확인하고 캐시를 재사용한다. 최초 다운로드와 엔진 초기화 자체를 없앤 것은 아니다.

## 입체감 이펙트

사용자 요청으로 `입체 효과` 켜기·끄기를 추가했다. 배경·전경의 미세한 시차, 먼 산의 옅은 안개, 낮의 빛줄기와 공간 입자, 밤의 모닥불 빛 번짐·캐릭터의 따뜻한 색 변화, 크기와 속도가 다른 불티로 깊이감을 표현한다. 2D 셰이더·프레임 스프라이트 위에 적용한 2.5D 표현이며 3D 맵·모델·물리·광원 가림 구현을 의미하지 않는다. 기존 진행 규칙과 저장 데이터는 바꾸지 않는다.

## 실제 3D 광원 비교 데모

사용자가 요구한 것은 깊이감 보정만이 아닌 실제 불빛·그림자임을 정정하여 별도 비교 모드를 구현했다. `보기 → 3D 광원 데모`에서 진입한다. `SubViewport`·`Camera3D`·실제 지면·텐트·테이블·나무 메시, 조명을 받는 알파 테스트 `Sprite3D` 캐릭터를 사용한다. 모닥불과 랜턴의 `OmniLight3D`가 물체를 비추고 그림자 맵을 생성한다. 불빛의 위치·밝기 변화에 따라 실제 그림자가 움직인다. 발광 화염 메시·3D 불티와 Compatibility 렌더러의 glow를 사용하며 `3D 그림자`로 비교할 수 있다.

픽셀 배경은 그림으로 완성된 이미지이므로 3D 데모는 같은 기획의 간단한 입체 캠프를 따로 렌더링한다. 기본 픽셀 모드의 생성 이미지 자체를 3D 지형으로 변환한 것은 아니다. 최종 게임의 3D 전환은 확정하지 않는다. 실제 Android 기기의 3D 프레임 속도·발열은 미검증이다.
