# 아이템·장소 어셋 제작 규칙

- 상태: 제작 규칙 초안 v0.1. 사용자 확정 방향과 AI가 제안한 제작 절차·형식을 구분한다.
- 변경일: 2026-11-27
- 담당: AI 제작·문서, 사용자 방향·시각 검토
- 관련: [제작 목록](asset-list.md), [현장 배치](../03-systems/placement.md), [원본 보관](../../art/source/README.md)

## 1. 이미 확정된 방향

- 배경·캐릭터·아이템 그림은 2D 도트 픽셀 어셋이다. 배치 좌표가 3D여도 장비를 입체 모델로 바꾸지 않는다.
- 게임 좌표는 **X/Y가 바닥, Z가 높이**다. Godot 내부 Y-up 좌표로 바꾸는 작업은 구현에서 처리한다.
- 현장 아이템은 회전을 지원해야 한다. 회전 각도·조작 방식·방향별 그림 수는 미정이며, MVP 90도 단위 회전은 AI 제안이다.
- 아이템은 화면에서 직접 드래그한다. 지면 또는 올릴 수 있는 받침 위에만 배치하며 공중에 띄우지 않는다.
- `stackable=true`는 **다른 물건을 위에 받칠 수 있다**는 뜻이다. 현재 테이블은 true, 텐트·의자·랜턴·버너·러그는 false다. 위에 올릴 물건 자체가 true일 필요는 없다.
- 장소마다 배치 가능 좌표와 금지 구역을 기록한다. 그림 속의 물·나무·바위와 실제 판정 영역이 맞아야 한다.
- 편집 중 가능 영역·점유 범위·받침 면은 코드로 표시한다. 선택 물건의 XYZ축과 Z축 위 완료 버튼도 그림에 그려 넣지 않는다. 완료 후 안내는 숨긴다.

아래는 이 방향을 지키기 위한 **AI 제작 규칙 초안**이다. 세부 수치·파일 구성은 수정할 수 있고, 새 콘텐츠나 최종 화풍을 확정하는 문서가 아니다.

## 2. 제작 시작 전에 정할 것

1. 제작 목록의 ID와 용도, 사용자 결정 근거를 확인한다. 기획에 없는 장비·장소·상호작용은 추가하지 않는다.
2. 기준 그림을 하나 지정해 색감·선 굵기·빛 방향·시점을 맞춘다. 현재 장비 기준은 `game/assets/pixel/camping-props.png`, 장소 기준은 `campsite-*-terrain.png`다. 기존 그림이 최종 아트 승인을 받은 것으로 간주하지 않는다.
3. 아이템은 화면 크기보다 먼저 게임 안의 점유 크기와 기준점을 정한다. 장소는 배치 가능 공간부터 정한 뒤 풍경을 만든다.
4. 승인된 크기·시점의 변경은 메타데이터와 검증 기록에 함께 남긴다. 이미지 크기나 투명 여백으로 게임 점유 크기를 추정하지 않는다.

## 3. 공통 그림·파일 규칙

- 게임용 출력의 기본안은 PNG다. 개별 아이템은 실제 알파 채널이 있는 RGBA로 만들고 흰색·체커보드를 배경처럼 그려 넣지 않는다.
- 픽셀 경계는 선명하게 유지하고 최근접 필터를 사용한다. 흐림, 임의 보간 확대, 서로 다른 픽셀 밀도를 한 화면에 섞는 것을 피한다.
- 캔버스 픽셀 크기, 불투명 그림 영역, 게임 단위 크기를 각각 기록한다. 최종 공통 해상도·타일 크기·픽셀 밀도는 아직 미정이다. 현재의 512px 장비 셀·1672×941 배경을 모든 신규 어셋의 고정 규격으로 만들지 않는다.
- 움직임·의상·낮밤 변형은 기준점과 구도를 유지한다. 움직임이 필요한 경우 프레임이나 분리된 효과로 만들며 이미지 일부를 늘여서 대신하지 않는다.
- 제목·버튼·XYZ축·좌표 숫자·선택 테두리·배치 가능 색은 이미지에 포함하지 않는다.
- 생성·수정 시 참조 이미지, 프롬프트, 도구, 출력 파일, 변경 목적을 기록한다. 외부 자원은 출처와 사용 조건을 함께 보관한다. 존재하지 않는 편집 레이어 원본을 있다고 기록하지 않는다.
- 기존 원본은 보존한다. 변경본은 버전 또는 변형 이름을 붙여 비교한 뒤 연결한다. 기존 경로·ID 변경은 참조와 저장 호환 영향을 먼저 확인한다.

## 4. 아이템 제작 규칙

| 기록할 항목 | 규칙 |
|---|---|
| 독립 그림 | 기본은 아이템 1종을 따로 조작할 수 있는 그림. 다른 장비·음식·배경을 함께 합성하지 않는다. 아틀라스 출력은 가능하지만 각 아이템의 영역을 명시한다. |
| 바닥 기준점 | 캔버스 왼쪽 위 기준 픽셀 피벗과 실제 지면 접촉점을 기록한다. 그림을 바꿔도 물건이 떠 보이거나 바닥 속으로 들어가지 않게 한다. |
| 현장 크기 | 바닥 점유 X/Y 크기와 시각 높이 Z를 별도로 기록한다. 투명 여백·선택 범위·충돌 범위를 구분한다. |
| 선택 범위 | 보이는 그림을 우선 잡을 수 있어야 한다. 작은 물건의 터치 영역은 UI에서 보완하며 PNG를 늘리거나 투명 여백 전체를 점유 범위로 쓰지 않는다. 현재 최소 터치 기준은 56 논리 단위다. |
| 받침 | `stackable`을 반드시 기록한다. true일 때만 상판 높이 Z와 로컬 X/Y 지지 범위를 함께 기록한다. 그림의 상판과 데이터의 받침 위치가 맞아야 한다. |
| 올려놓기 | 아이템 전체의 바닥 점유 범위가 받침 면 안에 들어와야 한다. false인 물건 위에는 얹지 않는다. 상세 무게 제한·자유로운 다단 쌓기를 새로 도입하지 않는다. |
| 현장 회전 | 회전 각도에 맞는 바닥 점유 범위·받침 면·그림 방향을 함께 관리한다. 90도 회전이라면 X/Y 점유 크기와 로컬 받침 범위도 회전한다. 지면 기준점과 저장 방향을 유지한다. |
| 운반 크기 | 트렁크의 2D 점유 셀·회전 규칙은 현장 크기와 별도 데이터다. 그림이 크다는 이유로 적재 셀을 바꾸지 않는다. |
| 그림자·빛 | 이동 가능한 물건의 그림자·랜턴 빛·불빛을 장소 배경에 고정해서 그리지 않는다. 이동·철거 시 함께 갱신하거나 제거될 수 있어야 한다. |
| 변형 | 설치·운반·점등 등의 별도 그림은 채택된 동작에 필요한 것만 만든다. 회전·반전 시 시점과 기준점이 깨지지 않는지 확인한다. |

비스듬히 보는 2D 장비는 그림 전체를 화면에서 기울이는 것만으로 현장 방향 회전을 대신하지 않는다. 시점에 맞는 방향별 그림 또는 검증된 표현을 준비하고 방향과 이미지 영역의 대응을 기록한다. 방향 수와 재사용/반전 가능 여부는 물건별로 검토한다. 트렁크 회전과 현장 회전은 별개이며, 현재 프로토타입의 rotated 불리언·그림 회전이 이 요구를 완성했다고 보지 않는다.

테이블 예: 테이블 그림과 의자·컵·랜턴 그림은 분리한다. 테이블은 `stackable=true`, 상판 높이와 지지 범위를 기록한다. 컵이나 랜턴을 그림에 미리 붙여 놓아 실제 배치 물건처럼 보이게 하지 않는다.

## 5. 장소·배경 제작 규칙

- **플레이용 배경은 빈 캠핑 자리다.** 사용자가 설치·이동·회수하는 텐트·의자·테이블·버너·랜턴·러그·음식·장작 등을 배경에 합쳐 그리지 않는다. 장비가 포함된 분위기 시안은 플레이용 빈 배경과 구분한다.
- 고정 산·숲·하늘·호수·울타리·다리 같은 환경은 배경에 둘 수 있다. 배치 영역 안에 고정 장애물이 보이면 금지 구역 데이터도 함께 만든다.
- 장소 ID마다 게임 Z-up 기준 배치 경계, 지면 높이, 금지 구역, 배치 간격과 시점 정보를 기록한다. 중심만 들어가는 것이 아니라 물건 전체의 점유 범위가 들어가야 한다.
- 배경과 좌표를 맞출 수 있도록 지면의 대응 지점 3개 이상을 그림 픽셀과 게임 XYZ 좌표 쌍으로 기록하는 방식을 초안으로 사용한다. 현재 런타임은 장소의 `view`로 투영하며 대응 지점의 자동 보정 기능이 구현된 것은 아니다.
- 물가·나무·바위 주변을 배치 가능한 평지처럼 그려 혼동시키지 않는다. 가능 바닥·제외 구역을 실제 게임에 겹쳐 확인한다.
- 낮·밤 변형은 같은 지형·카메라·구도·대응 지점을 유지한다. 시간대가 바뀌었다고 장비의 저장 위치가 다른 땅으로 이동해 보이면 안 된다. 변형은 별도 그림 또는 색/조명 처리 중 채택한 방식을 기록한다.
- 폰·커버 화면·펼친 폴드·PC의 크롭과 시점에서 배치 영역이 물·바위 위로 밀리거나 화면 밖으로 사라지지 않는지 확인한다.
- 물결·풀·불빛 등 구현된 효과를 사용하는 배경은 효과 적용 구역도 기록한다. 배경 구도를 바꿀 때 기존 셰이더 마스크·UV 구역을 함께 확인한다.

장소의 지면 높이와 아이템의 상판 높이는 구분한다. 현재 `campsites.json`의 `table_z`는 MVP 호환용 임시 값이며, 새 받침 제작의 기준은 아이템별 `surface_height`다.

## 6. 보관과 데이터 기준

| 구분 | 보관 위치·역할 |
|---|---|
| 규칙·제작 상태 | 이 문서와 [asset-list.md](asset-list.md) |
| 새 편집 원본·제작 메타데이터 | `art/source/items/<id>/`, `art/source/places/<id>/` |
| 신규 게임용 이미지 기본안 | `game/assets/pixel/items/<id>/`, `game/assets/pixel/places/<id>/` |
| 현재 아이템 받침 판정 기준 | `server/src/main/resources/gameplay/item-surfaces.json` |
| 현재 장소 배치 판정 기준 | `server/src/main/resources/gameplay/campsites.json` |
| 게임용 데이터 복사본 | `game/data/` — 기준 원본에서 동기화하며 양쪽을 따로 편집하지 않는다. |
| 시각 검토 캡처 | `design/mvp/previews/` — 원본 이미지와 구분한다. |

기존 `game/assets/pixel/`의 평면 파일 구조와 PNG·프롬프트는 보존한다. 신규 디렉터리는 제작 기본안이며 기존 에셋의 일괄 이동을 요구하지 않는다. 새 ID와 파일 이름은 영문 `snake_case`를 기본으로 하고 사용자에게 보이는 이름은 한국어로 관리한다.

[아이템 메타데이터 예시](../../art/source/templates/item.asset.example.json)와 [장소 메타데이터 예시](../../art/source/templates/campsite.asset.example.json)는 **작성용 초안**이다. `example_*`는 새 게임 콘텐츠가 아니며 null·미완료 항목을 채워야 한다. 이 예시 JSON을 만들었다고 게임에 자동 등록되지 않는다.

현재 현장 크기는 `MvpRules.bounds()`와 `camp_editor_3d.gd`의 `dimensions()` 등에도 구현되어 있다. 어셋 규격 변경 시 양쪽을 함께 맞춰야 하며, 작성용 메타데이터가 이 구현을 이미 대체했다고 기록하지 않는다. 등록 시 이미지 참조·아틀라스 영역·피벗·받침/장소 데이터·서버/클라이언트 판정을 함께 연결한다.

## 7. 제작 순서와 완료 기준

1. **명세:** 제작 ID·용도·기준 그림·크기·피벗·배치/운반 정보 작성. 미정은 미정으로 남긴다.
2. **초안:** 아이템은 투명 독립 그림, 장소는 빈 배경과 배치 영역을 한 세트로 만든다.
3. **등록:** 실제 출력 경로와 출처를 남기고 관련 게임 참조·판정 데이터를 갱신한다. 파일 존재만으로 등록 완료로 보지 않는다.
4. **화면 확인:** 실제 게임에서 폰 390×844·폴드 820×920·PC 1280×900을 현재 비교 크기로 확인한다. 최종 지원 기종·해상도를 이 값들로 한정하지 않는다.
5. **조작 확인:** 그림을 직접 잡기, 가장자리/겹침/금지 구역, 회전 전후 점유·그림·받침 정합성, 받침 위·지면 이동, 저장·재접속, 철거 후 잔상, 배치 완료 후 안내 숨김을 관련 변경 범위에서 확인한다. 코드가 바뀌지 않은 문서 초안만 작성한 경우 게임 검증을 했다고 주장하지 않는다.
6. **기록:** 원본/출처/메타데이터/연결/검증 상태를 각각 남긴다. PC 창 크기 확인과 실제 Android 터치·폴드 기기 검증을 구분한다.

최종 픽셀 밀도·팔레트·제작 해상도·원화 시점·방향별 그림 수는 후속 결정이다. 이 초안은 기존 어셋 전체의 규격 준수나 재제작 완료를 의미하지 않는다.
