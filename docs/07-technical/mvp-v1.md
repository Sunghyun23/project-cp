# 첫 완주 MVP — 구현 기준

- 상태: 웹 프로토타입 구현·시드니 배포, 검증 범위는 아래 기록 참고
- 변경일: 2026-11-28
- 담당: AI 구현·검증, 사용자 방향·시각 검토
- 범위: D117·D121~D123·D128·D133~D136

## 현재 이어지는 흐름

선택 이동 체험이 있는 웹 인트로 → Google/게스트 인증·복원 → 신규의 남성/여성 선택 → 월~금 간단 업무 또는 서류 검토 → 장소 → 장비 구매 → 날짜별 예보·의상·음식 준비 → 출발 적재 → 현장 배치 → 조리·먹기·휴식·취침 → 일요일 철거 → 귀가 적재 → 착불 택배함/수입/지출 정산 → 다음 주·재접속.

기본 계정·Google 연결·복구 코드는 기존 API를 재사용한다. 시작 버튼은 이동 체험을 하지 않아도 사용할 수 있다. 신규 복구 코드는 보관 안내를 거친 뒤 게임에 진입한다. 이미 로그인한 사용자는 시작 버튼으로 바로 진행을 복원하며 계정 관리는 `/?account=1`에서 연다. 인트로에도 `Google 로그인 · 계정` 바로가기를 항상 표시한다.

## 표현과 입력 — 기존 구현과 후속 교정

**좌표 교정(D140): 게임 사양은 X/Y 바닥·Z 높이다. 아래 X/Z 바닥·Y 높이 설명은 기존 Godot/API 구현 현황이며, [새 배치 명세](../03-systems/placement.md)로 변환·호환 처리가 필요하다. 로컬에서 Z-up 요청 변환·표시를 구현했고, 기존 저장 좌표는 호환을 유지한다. 2026-11-27 사용자 요청으로 시드니 공개 서버에 배포했다.**

배경·캐릭터·장비 그림은 모두 **2D 도트 에셋**이다. 현장을 통째로 3D로 교체하지 않는다. 2D 배경 위에 투명한 SubViewport를 겹치고, 그 안에서 Sprite3D에 2D 장비 이미지를 표시한다. 편집할 때만 알파 0.25의 옅은 격자를 보여주고 평소 숨긴다. 별도 바닥판·3D 캠핑장 박스·입체 장비 모델은 사용하지 않는다.

장비는 X·Y·Z 위치를 저장한다. X/Z는 바닥 방향, Y는 높이다. Y는 지면 또는 테이블 위로만 스냅하며 공중 부유를 허용하지 않는다. 테이블 위 물건은 상판 범위 안에 있어야 한다. 위 물건을 먼저 내려야 테이블 이동·철거가 가능하다. 서버는 보이지 않는 배치 범위로 겹침·범위·지지를 검사한다.

실어 온 미설치 장비는 D202의 하단 접이식 가져온 짐 목록에 둔다. 현장에는 설치품과 선택 후보 하나만 표시하며, 직접 잡아 끌어 위치를 미리 보고 확정하면 캐릭터가 다가가 설치 모션을 수행한 뒤 `place_item`으로 저장한다(D167). 취소하면 미설치품은 목록으로, 기존 설치품은 이전 위치로 복원할 수 있으며 미확정/설치/저장 중에는 다음 단계로 진행하지 못한다. 설치한 물건도 같은 방식으로 옮긴다. 마우스·단일 터치 드래그를 처리하며 작은 장비에도 최소 56 논리 픽셀의 선택 범위를 둔다. 지면/테이블 위 높이는 포인터 위치로 자동 판정한다. 저장 중에는 추가 드래그를 막고, 서버가 겹침·지지·범위를 거절하면 마지막 저장 위치(미배치면 준비 위치)로 되돌린다. 통신 실패로 저장 여부가 불명확하면 재조회를 요구한다.

배치 화면의 큰 박스는 기본으로 숨기고 `배치 완료` 버튼·짧은 안내만 남긴다. 축/숫자 입력은 숨기며, D167로 확정/취소 단계를 다시 도입했다. `장비` 메뉴는 선택품을 차로 되돌리는 보조 기능이다. 미배치품은 배치 완료 후 차에 남는다. 현재 장비의 시각 원본은 2D 생성 스프라이트 시트이며 방향별 그림·정교한 깊이 표현은 이후 개선 대상이다.

트렁크는 현장과 구분해 **2D 격자 퍼즐**을 유지한다. 펼친 그림·점유 모양 → 드래그로 적재/이동/회수하며 0/90/180/270도 회전한다. 물건 선택 후 칸 누르기도 유지하고, 키보드 방향/확인·R, 패드 방향/확인·Y도 처리한다. 이동은 터치/클릭 목적지 방식과 키보드/패드 직접 입력을 제공한다. 물리 장치 검증과 자동 입력 이벤트 검증은 구분한다.

### 마름모 격자 편집과 적재 표시

현장 편집은 45° 고정 방위와 30° 내려다보는 시점을 사용한다. 테이블과 의자 현장 그림은 같은 시점에 맞춰 네 방향을 그렸다. 화면에서 축과 좌표 숫자를 숨기고 초록·빨강 점유 범위로 배치 가능 여부를 표시한다. 상판에는 지정된 버너·랜턴만 자동 배치하며 바닥 물건은 서로 겹칠 수 없다. 트렁크에서는 품목별 색과 굵은 테두리를 표시하고 목록에 적재 완료 체크를 붙인다.

## 적재·소모·손실

시간 종료 시 정상 적재한 물건으로 자동 출발하며, `출발하기`로 일찍 마쳐도 같은 결과 처리를 적용한다. 못 실은 물건은 집 소유로 보존한다. 현장에서는 가져온 물건 중 원하는 것만 배치하고, 평소에는 격자를 숨긴다. 미배치품은 차에 그대로 있다.

귀가 전 설치품을 모두 철거하고 다시 적재한다. 귀가 타이머는 한 번만 진행하며 종료 시 결과를 확정해 정산으로 자동 연결한다. `귀가하기`로 일찍 마칠 수 있고 미적재품이 있으면 손실 확인을 요구한다. 이 자동 연결은 MVP UX 가정이다. 귀가 미적재품만 소유에서 제거하고 회수하지 못한다. 귀가 대상은 이번에 실제로 가져온 물건으로 한정하므로 집에 남긴 물건은 손실되지 않는다. 먹은 음식은 소모하고 귀가 적재 대상에서 제외한다. 남은 음식은 적재/손실과 다음 주 보존에 연결한다.

## 시간·네트워크·저장

활성 클라이언트의 짧은 tick 요청으로 적재 잔여 시간과 캠핑 시간을 저장한다. 비접속 동안은 감소시키지 않는다. 예보 열기로 시간을 멈추지 않는다. 캠핑은 활성 1초를 게임 1분으로 압축하고 취침 시 일요일 아침으로 연결하는 테스트 모델이며 전체 평일의 연속 시간 시뮬레이션을 완성한 것은 아니다. 현재 tick은 클라이언트 경과를 최대 2초씩 받는 프로토타입으로, 부정행위 방지용 시간 권위 서버가 아니다.

일반 행동·배치·tick은 기존 버전 검사·행 잠금으로 원자적으로 저장한다. tick 처리 중 사용자 행동은 최신 버전으로 이어서 보내며, 배치 판정 400 오류는 위치를 고칠 수 있게 표시한다. 통신 실패·충돌 등 저장 결과가 불명확하면 재조회부터 요구한다. 같은 구매·급여·소모를 화면 연출 때문에 다시 적용하지 않는다.

## 기존 진행 호환

새 진행은 `mvp_version=1` 규칙을 사용한다. 기존 데이터는 원본 단계·잔액·계정·캐릭터·기록을 보존한다. 캐릭터/업무/장보기/정산의 안전한 경계에서 명시적인 `upgrade_mvp` 행동으로 전환한다. 기존 캠핑 진행 중이면 그 주를 원래 규칙으로 마친 뒤 새 흐름으로 이어가며 강제 초기화하지 않는다. 이전에 실어 두었던 장비도 새 소유 목록에 보존한다. 서버가 조회 요청만으로 데이터를 변경하지 않는다.

## 알려진 미해결 문제

직접 드래그 배포 후 사용자가 XYZ 배치 의도와 다르고 배치가 잘 안 된다고 보고했다. 현재 자동 Y 스냅 방식이 의도한 조작을 충족한다고 확정하지 않는다. 입력/저장 자동 검사 통과와 별개로 현장 배치 UX는 재현·수정·사용자 재검수가 필요하다. [피드백 기록](../05-ux/reviews/2026-11-27-mvp.md#사용자-확인--배치-ux-미해결)

## 현장 90도 회전

사양을 먼저 main에 푸시한 뒤 MVP와 공개 서버에 반영했다. 선택품의 `회전 90°` 버튼·키보드 R·패드 Y는 0→90→180→270→0 순서로 방향을 바꾸고 저장한다. 회전 버튼과 완료 버튼은 Z축 위에 세로로 배치한다. 네 방향은 실제 2D 스프라이트를 교체하며 회전 후 점유/받침 범위를 함께 판정한다. 실패하면 기존 방향을 유지하고 위치를 먼저 옮기도록 안내한다. 받침 위 물건이 있으면 먼저 내린다.

방향은 rotation_degrees에 저장하고 rotated는 홀수 번 회전 여부로 유지한다. 기존 true/false 저장은 90/0으로 읽으며 구형 클라이언트의 같은 방향 이동도 기존 270도 같은 전체 각도를 보존한다. 서버 24개 테스트 및 공개 회전 저장/복원 검증 통과. Android 실제 장치 확인은 별도다.

2026-11-28의 풍경 감상·낮밤 미리보기·펼친 적재/4방향 테트리스 점유·조기 종료 기준은 [MVP 플레이 조작](../05-ux/screens/mvp-play-controls.md)을 따른다.

## 감상 이동·착석·설치 동작 — D165~D167

[캐릭터 동작 명세](../05-ux/screens/camp-actions.md)에 따라 감상 중 이동·의자 착석과 명시적 종료, 배치 확정/취소 후 캐릭터 이동·설치를 연결한다. 신규 `camp_actor.gd`는 장소 경계·나무 금지 구역·설치 장비를 피하는 0.25단위 경로와 세션 내 캐릭터 자세를 관리한다. 속도 2.4단위/초·손동작 1초는 AI의 프로토타입 수치다. 서버의 판정·STA 소모·진행 저장 계약은 유지하고, 실제 `place_item` 요청만 설치 완료 시 한 번 전송한다. 이동·착석은 로컬 시각 상태이며 재접속 시 기본 서 있는 상태다. 확정 전/저장 전 이탈은 미설치 상태로 남으며 저장 결과 불명확 시 재조회한다.
