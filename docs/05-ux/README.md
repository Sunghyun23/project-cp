전체 여정은 [유저 플로우](user-flow.md)를 기준으로 검토하고, 세부 화면 ID·연결은 [화면 흐름](screen-flow.md)에서 정의한다. 현재 플로우는 확정 기획과 AI의 UX 제안을 구분한 초안이다. 화면 방향과 게임 시점은 실제 화면 배치를 구체화할 때 정한다. 로딩·빈 상태·오류·앱 중단 후 복원도 검토한다.
일반 Android 스마트폰과 폴더블의 커버·내부 화면에서 다양한 해상도·화면 비율을 지원한다. 접기·펼치기·창 크기 변경 시 글자·버튼·HUD의 가독성과 입력 좌표를 유지한다. [화면 대응 사양](../07-technical/android.md)을 따른다.
Figma는 필요할 때 사용하고 화면 ID와 링크를 연결한다.

입력 장치 지원과 구체 조작은 [입력과 조작](../02-gameplay/controls.md)을 따른다. 터치·클릭·키보드·게임패드 모두 지원하는 요구가 확정되었으며 터치·클릭 목적지 이동과 키보드·패드 직접 이동, 웹·Android 공통 UI 방향도 확정했다. 구체 매핑·입력 전환 UX는 후속 정의한다.

현재 작업은 [첫 MVP 범위](../01-vision/scope.md#첫-mvp-범위--d117)에 한정한다. D125에 따라 저장소의 흐름·화면 명세 → Godot 공통 UI와 작은 플레이 단위 구현 → 화면·플레이 검증을 반복한다. Figma는 선택 도구다. 기존 장기 상세 플로우 전부를 첫 MVP 화면으로 구현하지 않는다.

## UX 관리 입구 — D125

[관리 방식과 MVP 화면 목록](workflow.md)을 기준으로 작업한다. 기존 `SC-` 화면·`ST-` 상태 ID를 유지하고 문서·이슈·구현 참조·검증 기록에서 같은 ID를 사용한다. 화면별 명세는 `screens/`, 실제 검증 기록과 캡처는 `reviews/`에 필요한 시점에 추가한다. 상세 명세의 첫 예시는 [캐릭터 선택](screens/character-select.md)이다.
