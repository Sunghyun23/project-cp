## 확정 요구와 구현 선택

사용자는 서류 분류 업무를 MVP에 추가하고 Papers, Please를 참고하며 미니게임이 화면을 꽉 채우도록 요청했다. 세 기존 비교안과의 차이를 설명한 뒤 방식 선택·구현·배포·푸시를 위임했다. 세 비교안은 이력으로 보존하고, 이번에는 문서 내용을 대조하는 한 가지 업무를 먼저 구현한다. 최종 평일 업무 유형 전체를 확정하거나 다른 두 안을 구현했다고 보지 않는다.

AI가 고른 MVP 규칙은 원본 발주서와 접수 청구서의 거래처·금액·납기일을 대조해 전부 같으면 `결재`, 하나라도 다르면 `보완 요청`이다. 20초 동안 원하는 만큼 서류를 처리한다. 제출하면 정오답과 해당 금액을 보여주고 다음 서류로 넘어간다. 불일치한 청구서 항목을 누르면 즉시 보완 요청을 제출한다. 장수·분류 항목·거래처 이름·난도·보상 수치는 테스트용이다. Papers, Please의 자산·서류 이미지·이야기는 사용하지 않는다.

## 진입·조작·복귀

평일의 `서류 검토 업무 시작`에서 들어간다. 기존 간단 업무도 선택할 수 있다. 캠핑 HUD나 작은 하단 대화상자를 겹치지 않는 별도 전체 화면 작업대다. 폰·폴드·PC에서 두 서류를 좌우로 나란히 놓고 각 항목의 이름과 값을 세로로 표시한다. 짧은 가로 화면은 여백과 안내를 줄여 두 서류의 항목과 도장 버튼이 한 화면에 들어오도록 한다. 업무 선택 화면과 서류 검토 화면에서 플레이어 캐릭터를 숨긴다.

- 일치하면 결재 버튼을 누르거나 접수 서류를 결재 도장으로 끌어 놓는다. 결재를 선택하면 두 서류 가운데에 큰 붉은 도장이 찍히는 애니메이션과 짧은 타격음이 재생된다. 정답 여부는 서버 응답으로 표시한다.
- 키보드 1로 결재하고 Tab·방향 키와 확인으로 청구서 항목을 선택한다. 패드는 방향·A 확인을 사용한다. Esc 또는 `잠시 나가기`로 업무 선택 화면에 돌아간다.
- `잠시 나가기`와 재접속은 처리 건수·오답 횟수·현재 서류를 보존한다. 서류 진행이 있으면 `이어하기`를 제공한다.
- 저장 중에는 판단·드래그·나가기 중복 입력을 막는다. 통신 결과가 불명확하면 재조회부터 요구한다.
- 화면에 남은 초, 처리 건수, 누적 급여를 표시한다. 정답은 2원, 오답은 1원이며 마감 시 미제출 서류는 정산하지 않는다. 20초가 끝나면 `퇴근하기`로 누적 급여와 STA -6을 한 번 반영한다. 금요일이면 장소 선택으로 간다.
- 업무 화면을 닫거나 비접속 중에는 시간이 흐르지 않는다. 시작한 서류 업무는 같은 날 이어서 마친다.

이 업무는 첫 MVP의 선택 가능한 미니게임이다. 20초 근무는 D116의 시간·처리량 기반 급여를 서류 검토에 적용한 규칙이다.

## 데이터와 판정

`DocumentWork.java`가 주차·요일·처리 순번으로 매번 같은 비교 서류를 생성한다. `office_task`에 순번·오답·누적 급여·남은 시간·진입 여부를 저장하고 응답의 `office_case`로 현재 원본/접수 서류를 제공한다. `office_start`, `office_review`, `office_pause`, `office_finish`는 기존 버전 검사·트랜잭션을 사용한다.

현재 전표 ID가 아닌 요청·잘못된 판단 종류·미완료 퇴근은 거절한다. 정답 판정과 진행/급여는 서버가 계산하고 클라이언트의 위조 진척 값을 사용하지 않는다. 완료 시 업무 데이터를 정리해 중복 퇴근으로 같은 급여를 받지 못한다. 기존 계정/저장·간단 업무·캠핑 데이터는 보존하며 DB 스키마 변경은 없다.
