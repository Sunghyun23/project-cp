## 요청과 구현 범위

사용자는 바뀌는 기획을 간단한 에셋으로 플레이해 보고, 이 과정에서 서버 환경도 구성하기를 요청했다.
평일 5일 → 장보기 → 짐 싸기 → 현장 설치 → 자유 휴식 → 저녁 요리 → 불멍·취침 → 아침 → 철수 → 정산·다음 주를 연결한다. 업무·선택 알바로 돈을 얻고 스탯을 소모한다. 재료·장비를 선택하고 요리·휴식으로 회복한다. 소지금·스탯·레시피 기록은 다음 주에도 유지된다.

## AI의 임시 가정

아래는 실행 가능한 테스트를 위한 가정이며 사용자 확정 기획이 아니다.

- 임시 제목 `이번 주말은 캠핑`, 2D Control과 코드로 그린 산·나무·텐트·밤하늘. 최종 2D/3D·시점·화면 방향은 미정이다.
- 15분 목표를 기다림 없이 압축한다. 업무는 하루 버튼 1회, 설치·철수는 각각 3회다. 사무 업무 비교안의 최종 채택을 의미하지 않는다.
- 장보기 가격에 아침 재료도 포함한다. 트렁크 배치 대신 텐트·테이블·의자를 선택하고 텐트 방향 조작은 생략한다.
- 기본 가스 장비와 고급 숯불 장비는 무료로 교체해 비교한다. 최종 가격·해금 조건이 아니다.
- 라면은 한 종류, 꼬치는 고기·버섯 총 3개를 고른다. 재료 순서와 무관하게 같은 조합을 같은 레시피로 본다. 직접 끼우기·불 조절은 버튼으로 대체한다.
- 기본 조리 3회·별 2개, 고급 조리 2회·별 3개. 이미 별 3개인 레시피를 3회 더 조리하면 숙련도 최대·별 4개다. 숙련도는 체력 회복에 가산한다.
- 힘·행운·체력 상한 100. 회복·소모·급여·구매 수치는 `server/prototype/rules.py`의 임시 값이다. 힘의 적재·설치 보정과 행운 확률 이벤트는 미구현이다.
- 휴식 효과는 단계당 한 번이다. 자동 진행하지 않고 `다음`을 누를 때 이동한다.
- 아침은 커피·토스트 합쳐 버튼 1회다. 상세 조리·레시피 해금·별똥별 제안은 미구현이다.

## 서버 구성

```text
Godot macOS → 127.0.0.1:8000 → Django API → PostgreSQL
브라우저 → localhost:8080 → Caddy → Godot Web
                            └ /api/ → Django API
```

`POST /api/v1/prototype/sessions/`는 임시 세션, `GET /api/v1/prototype/state/`는 저장 조회, `POST /api/v1/prototype/actions/`는 행동 처리다. `GET /api/v1/health/`는 DB 연결을 확인한다.
임시 세션은 무작위 토큰을 발급하고 DB에는 해시만 저장한다. 서버가 단계·선행 조건·버전을 확인하고 트랜잭션으로 저장한다. 오래된 버전은 409로 거부하며 저장 다시 불러오기로 복구한다. 네트워크 오류 시 서버 저장 여부가 불명확할 수 있으므로 다시 불러온 뒤 진행한다.

임시 토큰은 정식 게스트 계정 방식을 대체하지 않는다. 공개 서비스용 가입·인증·복구·요청 제한은 제공하지 않으며 루프백에서만 사용한다. AWS 리소스는 생성하지 않았다. 운영 Lightsail·별도 EC2 DB 선택은 유지한다.

## 다음 검증

기획자가 직접 한 주를 눌러 흐름·선택의 재미·빠진 행동을 확인한다. 그 결과로 사무 업무·짐 배치·요리 중 직접 조작할 부분과 시간·수치를 조절한다. 전체 흐름 구현이 최종 MVP나 상세 규칙 확정을 의미하지 않는다.
