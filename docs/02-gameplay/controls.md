## 확정 요구

게임 조작과 UI는 **터치·마우스 클릭·키보드·게임패드**를 모두 지원하는 방향으로 설계한다(D048). 로그인 전의 가벼운 이동 체험도 이 지원 범위에 포함한다. 화면 크기나 플랫폼 이름만으로 특정 입력 장치를 배제하지 않는다.

터치·클릭은 **누른 위치를 목적지로 지정해 이동**한다. 키보드·게임패드는 **입력 방향에 따라 캐릭터를 직접 조작**한다(D049). 이 방향은 로그인 전 이동 체험에도 동일하게 적용한다. 목적지 지정 이동을 위해 가상 스틱을 기본 UI로 추가하지 않는다.

웹과 Android는 같은 인터페이스를 사용한다(D049). 주요 버튼·메뉴·진행 흐름·행동의 의미를 공통으로 두고, 폰·폴드·웹의 크기에 맞게 배치한다. 기존 반응형 배치 요구를 폐기하거나 모든 화면에서 픽셀 위치를 고정하는 뜻으로 해석하지 않는다. 키보드·패드에서도 공통 UI를 조작할 수 있도록 포커스와 입력 안내를 구체화한다.

## 입력별 확정·미정

| 입력 | 확정된 이동 방식 | 후속 정의할 내용 |
|---|---|---|
| 터치 | 누른 위치를 목적지로 지정해 이동 | 이동 가능 영역·목적지 표시·새 목적지 지정·길이 막힌 경우 처리 |
| 마우스 클릭 | 클릭한 위치를 목적지로 지정해 이동 | 버튼 매핑·목적지 표시·누르고 있기·보조 클릭의 처리 |
| 키보드 | 방향 입력으로 캐릭터 직접 조작 | WASD·방향키 등 키 배치, 메뉴 포커스·확인·취소 |
| 게임패드 | 방향 입력으로 캐릭터 직접 조작 | 스틱·방향 패드 선택, 확인·취소 버튼, 아날로그 입력·데드존 |

구체 키·버튼 배치, 이동 속도·정지·충돌·경로 탐색·입력 간 우선순위는 아직 미정이다. 모든 게임패드 모델·OS·브라우저 조합의 호환성 검증을 완료한 것은 아니다.

텍스트 입력이 필요한 로그인·가입에서 소프트 키보드·물리 키보드·게임패드 사용 환경을 어떻게 연결할지도 후속 정의한다. 입력 방식 추가를 이유로 익명 계정이나 다른 로그인 정책을 새로 채택하지 않는다.

## UX 설계 제안

다음은 지원 요구를 구현하기 위한 AI 제안이며 세부 규칙 확정과 구분한다.

- 입력별로 게임 결과와 주요 행동이 같도록 논리적 행동과 실제 키·버튼을 분리한다. 각기 다른 입력으로도 인트로 진입·이동·시작·인증 화면 접근이 가능하도록 검토한다.
- 키보드·게임패드로 버튼과 메뉴를 탐색할 때 현재 선택 위치가 보이고, 막힌 포커스나 빠져나갈 수 없는 패널이 없도록 한다. 클릭만 가능한 버튼으로 남기지 않는다.
- 터치로 UI를 누른 행동이 같은 위치의 캐릭터 이동까지 발생하지 않게 한다. 메뉴를 닫을 때의 확인 입력도 뒤의 게임 행동으로 중복 전달하지 않는 방향을 제안한다.
- 장치가 바뀌어도 현재 선택·패널·플레이 단계는 유지한다. 입력 힌트가 필요하면 사용 중인 장치에 맞추되, 장치 전환을 위한 설정 화면 방문을 강제하지 않는 방향을 검토한다.
- 스틱의 작은 흔들림으로 안내가 계속 바뀌거나 메뉴가 이동하지 않도록 한다. 데드존·입력 반복·장치 연결 해제 처리의 값과 정책은 미정이다.
- 목적지 이동 중 키보드·패드의 직접 이동을 시작하면 목적지 자동 이동을 중단하고 직접 입력으로 전환하는 안을 제안한다. 키·패드를 놓았을 때 오래된 목적지로 다시 출발하지 않게 한다. 이는 확정된 이동 방식을 연결하는 상세 UX 제안이다.
- 목적지 표시·메뉴 포커스·조작 안내는 공통 UI와 어울리게 구성하고, 입력 방식 때문에 캐릭터·풍경·진행 버튼을 가리는 별도 조작 패널을 추가하지 않는 방향을 제안한다.

## 검증 계획

| 시나리오 | 확인할 것 | 현재 |
|---|---|---|
| 터치만 사용 | 누른 위치로 이동·UI 선택·시작·뒤로 가기, UI와 이동 입력의 중복 방지 | 요구 정리, 전체 미검증 |
| 마우스만 사용 | 클릭 위치로 이동·UI 선택·시작·닫기 | 기존 프로토타입의 일부 이동·버튼 확인. 새 인트로는 미구현 |
| 키보드만 사용 | 직접 이동·메뉴 포커스·확인·취소, 조작 불가능한 지점 유무 | 미구현·미검증 |
| 게임패드만 사용 | 직접 이동·포커스·확인·취소, 연결 해제 안내와 복귀 | 미구현·미검증 |
| 장치 전환 | 진행·포커스 유지, 중복 행동·안내 반복 방지 | 미검증 |
| 폰·폴드·웹 | 크기 변경 후 입력 좌표·UI 포커스·행동 유지 | 브라우저 배치 검증과 별도. 실기기 입력 조합 미검증 |

기존 이동 체험 프로토타입의 클릭 구현이나 브라우저 크기별 화면 확인을 네 입력 전체 지원 완료로 간주하지 않는다. 이 문서 작성으로 게임 코드를 변경하지 않았다.
