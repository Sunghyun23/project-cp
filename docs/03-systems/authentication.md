# 로그인과 계정

- 상태: 웹 프로토타입 구현, 웹 Google 로그인 사용자 확인 완료, Android 연동 검증 별도
- 담당: 기획자 + AI
- 관련 문서: [결정 기록](../decisions.md), [기술 설계](../07-technical/README.md)

## 확정 사항

- 로그인 기능을 도입하고 Google 로그인을 직접 연동한다.
- Google 로그인 없이 게스트로 플레이할 수 있어야 한다. Android와 웹 모두 게스트 인증을 지원한다.
- 게스트는 명시적인 인증 정보를 입력하여 다른 브라우저나 Android 앱에서도 같은 계정으로 이어할 수 있어야 한다. 인증 정보는 사용자가 직접 정하는 ID·비밀번호로 한다.
- 게스트로 플레이한 뒤 Google 계정에 연결해 기존 진행 상황을 유지할 수 있어야 한다.
- Google 연결 후에도 기존 ID·비밀번호 로그인을 유지한다. 두 로그인 방식은 동일한 게임 계정과 진행 상황으로 연결한다.
- Google 연결 전 비밀번호를 분실했을 때 사용할 복구 코드 기능을 제공한다. 문자·이메일 발송 없이 자체 서버에서 처리한다.
- 서버 호스팅 비용을 제외한 운영비용은 0원이어야 한다.
- 자체 서버에서 Google 인증 결과를 검증하고 게임 계정과 연결하는 방향으로 설계한다.
- 인증 횟수·사용자 수에 따른 유료 인증 서비스, 문자 발송, 유료 이메일 발송에 의존하지 않는다.

## 구현 방향 — 상세 설계 시 검증

Android는 지원되는 Google 로그인 경로를 Godot에 연결한다. 웹용 로그인 경로도 구성한다.
클라이언트의 로그인 성공 표시만 신뢰하지 않고 서버에서 ID 토큰의 서명, 발급자, 대상 클라이언트, 만료 등을 검증한다.
Google 계정 식별은 이메일 대신 검증된 발급자와 sub를 기준으로 하고, 내부 게임 계정 ID와 연결한다.
게임용 세션의 발급·만료·로그아웃 규칙은 별도로 설계한다. 비밀키와 인증 토큰은 저장소나 로그에 남기지 않는다.

Google 직접 로그인과 Firebase Authentication 같은 관리형 인증 서비스는 구분한다.
현재 인증 사용료 없이 구성 가능한 방향을 선택한 것이며 외부 제공자의 정책이 영구히 유지된다고 보장하는 것은 아니다.
서버·DB·트래픽·백업 등의 비용은 호스팅 예산 안에서 검토하고, 도메인 등 추가 유료 자원도 임의로 도입하지 않는다.

## 게스트 인증 — 사용자 지정 ID·비밀번호 확정

브라우저에서 읽는 IP, User-Agent, 화면 크기 등은 고유하거나 비밀인 값이 아니므로 인증 수단으로 사용하지 않는 방식을 제안한다.
Android 앱과 같은 기기의 브라우저는 저장 공간을 공유하지 않아 이런 정보만으로 동일한 사람임을 증명할 수 없다.

### 제안하는 흐름

1. 사용자가 직접 정한 ID·비밀번호로 게스트 계정을 생성한다. 자동 발급 비밀 로그인 코드 방식은 채택하지 않는다. ID의 중복 확인·정규화·허용 문자와 비밀번호 규칙은 상세 설계 시 결정한다.
2. 다른 브라우저나 Android 앱에서 인증 정보를 명시적으로 입력하면 서버가 검증하고 같은 게임 계정으로 로그인시킨다. 로그인용 장기 인증 정보와 재접속용 세션 토큰은 구분한다.
3. 웹은 서버가 설정하는 Secure·HttpOnly 쿠키, Android는 Keystore로 보호하는 저장 방식을 우선 검토한다. 웹의 배포 도메인과 요청 방식에 맞춰 쿠키·CSRF·CORS 구성을 검증한다.
4. 재접속 시 비밀 인증 정보를 검증하여 기존 게스트 계정을 사용한다. 공개 계정 ID나 클라이언트가 주장하는 기기 ID만으로 인증하지 않는다.
5. 비밀번호는 원문이나 복호화 가능한 형태로 저장하지 않고, 검증된 비밀번호 해시 라이브러리와 계정별 salt로 처리한다. 로그인 시도 제한과 오류 응답 정책을 설계한다.
6. 토큰은 서버에서 안전한 해시 등으로 관리하고 만료·교체·폐기와 발급 요청 제한을 설계한다. 전송에는 HTTPS를 사용한다.

이는 외부 유료 인증 서비스 없이 자체 서버에 구현할 수 있는 제안이다. 저장·세션 방식은 구현 전 확정한다.
웹에서 저장이 차단되거나 삭제된 경우, 시크릿 모드 종료, Android 앱 데이터 삭제·재설치 시 게스트 인증 정보가 사라질 수 있다.
세션 저장 정보가 없어져도 명시적인 인증 정보가 있으면 재인증하여 이어할 수 있어야 한다. 비밀번호 분실 시 복구 코드를 사용할 수 있어야 한다. 비밀번호와 복구 코드를 모두 잃은 경우의 정책은 미정이다.

### Google 계정 연결

게스트로 인증된 상태에서 Google 인증도 완료하면 기존 진행 상황을 보존하며 연결한다. 기존 내부 계정에 Google 인증 수단을 추가하는 방식을 제안하며, 새 계정으로 데이터 복사·병합이 필수라고 가정하지 않는다.
게스트 접근 권한과 Google 인증 결과를 서버에서 모두 검증하고, 연결 처리는 중복 요청에도 일관성을 유지하도록 설계한다. 이미 다른 계정에 연결된 Google 계정을 자동으로 덮어쓰지 않는다.
연결 후에도 ID·비밀번호를 폐기하지 않는다. Google 로그인과 ID·비밀번호 로그인 모두 기존 게임 계정으로 접속하며 별도 진행 데이터를 만들지 않는다.

### 복구 코드

도입은 확정이다. 아래는 구현 방향 제안이며 코드 형식·발급 시점·개수·재발급 UI는 상세 설계 시 정한다.

- 서버가 충분한 엔트로피의 난수 복구 코드를 생성하고 사용자가 별도로 보관할 수 있게 안내한다. ID·비밀번호를 대신하는 일상 로그인 코드와는 구분한다.
- ID와 복구 코드를 검증하여 해당 계정의 비밀번호를 재설정하는 흐름을 제안한다. 진행 상황과 내부 계정 ID는 유지한다.
- 코드 원문은 서버 저장소·로그에 남기지 않고 검증용 해시 등으로 관리한다. HTTPS 전송, 입력 시도 제한, 비밀 값 노출 방지를 적용한다.
- 사용한 코드는 원자적으로 폐기하여 동시 요청·재사용을 막는다. 재발급 시 이전 코드의 폐기와 사용자 보관 안내를 설계한다.
- 복구 성공 후 기존 세션 처리, 새 코드 발급, Google 연결 후 코드의 유효 범위는 미정이다.
- 비밀번호와 복구 코드를 모두 잃은 경우 별도 근거 없이 계정을 복원해 준다고 가정하지 않는다.

### 추가로 결정할 사항

- ID·비밀번호 입력 규칙, ID 변경 허용 여부, 비밀번호 변경 절차.
- 복구 코드의 발급 시점·형식·개수·재발급과 분실 시 정책.
- 이미 진행 데이터가 있는 Google 계정에 연결할 때 선택·병합 정책.
- ID·비밀번호 로그인 끄기는 추후 후보이며 현재 구현 범위에는 포함하지 않는다. 향후 도입 시 Google 재인증·대체 로그인 수단 확인·복구 코드 처리를 함께 설계한다.
- 게스트 인증 정보가 없거나 저장 불가능한 환경에서의 안내와 플레이 정책.

## 미정

- 게스트 시작·Google 로그인 진입 UI와 전환 정책.
- 로그인이 필요한 기능과 오프라인에서 가능한 범위.
- 웹 배포 주소와 브라우저 지원 범위. 웹 빌드 제공과 공통 API 사용은 확정했다.
- 계정 간 전환, 탈퇴, 데이터 보존·삭제, 세션 만료 정책.
- 기기 간 이어하기를 위한 저장 시점, 동시 접속·데이터 충돌 규칙. 실시간 동기화까지 확정한 것은 아니다.
- 서버 프레임워크, 데이터베이스, Godot 연결 방식, OAuth 클라이언트 설정.

## 구현 시 확인할 검증 항목

- 정상 Google 로그인과 동일 계정 재로그인 시 계정 연결.
- 로그인 취소, 네트워크 장애, 잘못된·만료된 토큰, 대상이 다른 토큰의 거부.
- 로그아웃과 세션 만료 후 접근 처리.
- 복구 코드로 비밀번호 재설정 시 계정·진행 유지, 이전 비밀번호 거부.
- 잘못된·사용된·폐기된 복구 코드 거부, 재발급·동시 복구 요청·시도 제한 검증.
- 복구 코드 원문이 서버 저장소·로그에 남지 않는지 확인.
- 서로 다른 사용자의 데이터 접근 차단.
- 사용자 지정 ID·비밀번호로 계정 생성·로그인, 중복 ID·잘못된 비밀번호 처리, 입력 규칙과 시도 제한 검증.
- 임의 계정 ID만으로 인증 불가, 유효하지 않은 토큰 거부, 비밀번호 원문 저장·로그 노출 여부 확인.
- Android·웹에서 명시적인 인증 정보로 동일 계정에 재접속하고 기존 진행 상황 확인.
- 게스트에서 Google 연결 후 진행 보존, 다른 환경에서 Google 로그인 후 동일 계정 확인.
- Google 연결 후에도 기존 ID·비밀번호로 동일 계정에 로그인할 수 있고, 두 방식으로 같은 진행 상황에 접근하는지 확인.
- 연결 중단·재시도·중복 요청·이미 연결된 Google 계정의 충돌 처리. 상세 정책은 결정 후 검증.
- 웹 저장 차단·삭제와 앱 데이터 삭제 시 안내 및 Android·웹 저장 공간 분리 확인.
- Android 실제 로그인 경로 검증. 웹 경로와 계정 연결도 검증.

## 2026-11-26 웹 프로토타입 구현

사용자 요청으로 별도 로그인 화면, 게스트 가입·로그인·복구, Google 로그인·게스트 계정 연결, 로그아웃을 구현했다. 아래 세부 값은 AI의 초기 구현 기준이며 변경 가능한 프로토타입 정책이다.

- ID: 소문자 정규화, 영문·숫자·밑줄 3~24자. 비밀번호: 12자 이상·UTF-8 72바이트 이하, BCrypt 비용 12와 계정별 salt. 비밀번호 원문은 보관하지 않는다.
- 복구 코드: 가입·복구 때 난수 32바이트를 Base64URL로 한 번 표시한다. DB에는 SHA-256 해시만 저장한다. 복구 시 원자적으로 교체하고 해당 계정의 기존 모든 게임 세션을 폐기한다. Google 연결 후에도 같은 복구 규칙을 유지한다.
- 웹 게임 세션: 난수 32바이트·DB 해시·7일 만료, HttpOnly·SameSite=Lax 쿠키. 공개 HTTPS에서 Secure를 설정한다. 로그아웃은 현재 게임 세션을 서버에서 폐기하며 Google 자체에서는 로그아웃하지 않는다.
- 브라우저의 변경 요청에는 허용 Origin과 사용자 정의 요청 헤더를 요구한다. 로그인 관련 변경 요청은 프로세스 내 IP별 분당 30회 제한을 적용한다. 서버 재시작 시 제한 카운터는 초기화된다.
- Google Identity Services 공식 버튼·팝업을 사용한다. 서버가 공개키로 서명·발급자·대상 클라이언트·만료·nonce를 검증한 뒤 `sub`로 연결한다. 메일 주소로 자동 병합하지 않는다. OAuth 클라이언트 시크릿은 이 경로에 필요하지 않다.
- 기존 게스트로 로그인한 상태에서 Google를 연결하면 내부 계정과 진행 ID를 유지한다. 다른 계정에 연결된 Google 계정은 409로 거부하며 자동 병합하지 않는다. 기존 ID·비밀번호를 유지한다.
- Google로 처음 가입하면 해당 Google 계정의 새 진행을 만든다. 이전 익명 프로토타입의 로컬 토큰 진행을 자동으로 가져오지는 않는다. 기존 토큰과 데이터는 호환 API에 보존한다. Google 계정에 게스트 ID·비밀번호를 나중에 추가하는 화면은 아직 없다.
- 사용자 제공 웹 클라이언트 ID를 환경변수에 설정한다. 로그인 화면과 서버가 같은 설정을 사용한다. 2026-11-26 공개 HTTPS 주소에서 사용자가 본인 Google 계정으로 실제 로그인 성공을 확인했다.

서버 테스트로 게스트 재접속·계정 분리·Google 연결 후 진행 유지·연결 충돌·복구 재사용 거부·세션 만료·로그아웃·Origin 거부를 확인했다. Google 서명·발급자·audience·만료 검증은 로컬 RSA 공개키로 검사했으며 연결 통합 테스트의 Google 신원은 테스트 대역을 사용했다. 실제 Google 계정 로그인 성공을 이 테스트로 대신하지 않는다.

Android 네이티브 Google 로그인·안전한 세션 저장은 아직 구현·검증하지 않았다. 웹 로그인 성공을 Android 구현 완료로 간주하지 않는다.
