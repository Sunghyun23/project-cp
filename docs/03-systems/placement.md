# 현장 배치 — 좌표·받침 속성

- 상태: 장소 좌표·stackable 요구 확정, 표시/조작 방향 확정·공개 배포, 사용자 재검수 대기
- 변경일: 2026-11-27
- 담당: AI 구현·문서, 사용자 방향·시안 검토

## 사용자 확정

2D 배경·2D 장비 이미지를 유지하고 현장 배치는 XYZ 공간 좌표를 사용한다. **게임 좌표는 X/Y가 바닥 위치, Z가 높이다.** Godot 엔진 내부 좌표와 구분하며 `Vector3(game_x, game_z, game_y)`로 변환한다. 지면 또는 받침 위로만 놓으며 공중 부유는 허용하지 않는다. 큰 박스를 숨기고 물건 자체를 드래그한다. 장소마다 배치 좌표·금지 구역을 데이터로 기록하고 화면과 서버가 같은 범위를 사용한다.

`stackable`은 **다른 아이템을 위에 얹을 수 있는 받침인지**를 나타낸다. 테이블은 true, 텐트·의자·랜턴·버너·러그는 우선 false다. 위에 놓을 물건의 stackable 여부와 혼동하지 않는다. false인 물건에는 다른 아이템을 올릴 수 없다. 로컬 서버·클라이언트는 테이블 ID 전용 판정 대신 이 속성을 확인한다. 기준은 `server/src/main/resources/gameplay/item-surfaces.json`이며 게임용 복사본은 `game/data/item-surfaces.json`이다. 상판 높이·지지 범위가 함께 필요하며 자유로운 다단 쌓기의 도입을 뜻하지 않는다.

## 표시 방식 — 사용자 확정

전체 입체 격자 시안을 검토한 뒤 선택 물건의 축만 표시하는 방향으로 정했다.

- 선택한 물건에 빨강 X·초록 Y·파랑 Z만 표시한다. X/Y는 바닥, Z는 높이다.
- 편집 중 배치 가능 바닥만 옅은 연두색으로 칠하고 점선 경계를 표시한다. 금지 구역은 채우지 않고 따로 경계를 표시한다.
- 드래그 중 아이템 점유 범위는 초록(가능)/빨강(불가)으로 표시하고 이유를 안내한다. stackable=true인 받침의 표면도 강조한다.
- `배치 완료` 버튼은 선택 아이템의 Z축 끝 위에 붙인다. 이동·리사이즈에 따라 위치를 다시 계산하며 화면 안으로 보정한다. 드래그/저장 중에는 중복 완료를 막는다.
- 완료 후 축·가능 영역·점유 표시·받침 강조·완료 버튼을 모두 숨긴다.

폰·폴드 크기 렌더링과 입력 경로 검사는 로컬에서 통과했다. 시안 검토 후 사용자 배포 요청에 따라 2026-11-27 시드니 공개 서버에 반영했다.

## 장소 데이터

기준 원본: `server/src/main/resources/gameplay/campsites.json`. 웹 빌드 시 `game/data/campsites.json`으로 복사하며 서버 응답의 placement_site도 같은 원본을 사용한다. 현재 테스트 단위는 최종 미터 스케일이 아니다.

| 장소 | 게임 X 범위 | 지면 Z | 게임 Y 범위 | 금지 구역 | 받침 높이 Z |
|---|---|---|---|---|---|
| 호숫가 | 0~8 | 0 | 0~6 | 없음 | 테이블 0.9 |
| 소나무 숲 | 0~10 | 0 | 0~7 | X 0~1.4 / Y 0~1.4 나무 구역 | 테이블 0.9 |

아이템 중심뿐 아니라 전체 점유 범위가 허용 영역 안에 있어야 한다. 위 범위는 기존 MVP 테스트 수치를 문서화한 것이며 신규 장소 콘텐츠 확정과 구분한다.

## 좌표 변환·기존 저장 호환

장소 JSON schema_version=2는 X/Y 바닥·Z 높이로 기록한다. 클라이언트/서버는 엔진 계산 시에만 Y-up으로 변환한다. 새 드래그 요청은 `coordinate_system: z_up`을 명시하고 서버가 내부 좌표로 변환한다. 기존 무표시 요청·저장 field는 Godot Y-up 해석을 유지하므로 이전 진행을 이름만 바꾸어 잘못 해석하지 않는다. 응답의 `field_coordinate_system`으로 내부 저장 기준을 알린다. 사용자 좌표 표시와 시안은 Z-up이다.
